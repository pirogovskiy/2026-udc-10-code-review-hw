# Пайплайн рев’ю

## Що робить `pipeline/ai-review.yml`

1. Запускається на `pull_request` при відкритті, оновленні, повторному відкритті та переведенні PR у готовий стан. Для тестування checkout бере GitHub merge ref PR.
2. Job `deterministic-checks` встановлює Node.js 22 і запускає `npm test` у `app/`. AI-job має `needs: deterministic-checks`, тому не стартує, якщо тести не пройшли.
3. Job `ai-review` збирає diff, передає його GitHub Copilot CLI через `actions/ai-inference` із системним промптом `review/prompt.yml` і стандартом `docs/review-standard.md`, а потім публікує відповідь як звичайний коментар PR. Результат дорадчий і не є автоматичним схваленням.
4. Злиття затверджує людина відповідно до branch protection та правил репозиторію.

У форку потрібно додати секрет репозиторію `COPILOT_GITHUB_TOKEN` із доступом, потрібним Copilot CLI, та переконатися, що для акаунта доступний GitHub Copilot. Job AI-рев’ю навмисно пропускається для PR з форків: його умова дозволяє запуск лише тоді, коли джерельний репозиторій PR збігається з базовим.

## Права і секрети

На рівні workflow всі права вимкнені (`permissions: {}`). Job тестів отримує лише `contents: read`. AI-job додає `issues: write` для коментаря, `pull-requests: read` для метаданих PR, `contents: read` для файлів і `models: read` для інференсу. Токен Copilot передається тільки AI-job і тільки у same-repository PR; секрети не надаються коду з fork PR. Не використовується `pull_request_target`.

## Модель загроз

| Що може зробити PR зі шкідливим вмістом | Що обмежує шкоду у цьому пайплайні |
|---|---|
| Спробувати prompt injection в описі, diff чи коментарі, щоб змусити модель ігнорувати стандарт. | Промпт явно визначає весь вміст PR як недовірені дані та просить лише текстовий огляд. Висновок є дорадчим і перевіряється людиною. |
| Додати код, що викрадає секрет або виконує небажану дію під час тестів. | AI-job не запускається для fork PR і залежить від успішних тестів. Тестовий job не має секретів, write-дозволів чи доступу до токена Copilot. Не використовуємо `pull_request_target`. |
| Спробувати використати токен для запису в репозиторій або зміни PR-коду. | Copilot token наявний лише в AI-job, інференс не отримує інструментів для редагування; `GITHUB_TOKEN` має тільки потрібні права на читання і створення коментаря. Для fork PR AI-job пропускається. |
| Спричинити хибну або неповну рекомендацію, надто великий diff чи відмову моделі. | AI-висновок не є обов’язковим схваленням і не зливає зміни. Людина перевіряє висновки; детермінований тестовий job лишається окремим обов’язковим check. |

## Що лишається на людину

Людина перевіряє правильність знахідок, ризики, які модель пропустила, і відповідність домовленостям команди. Налаштування branch protection має зробити тестовий check обов’язковим. Коментар AI не замінює людське схвалення й не може бути єдиною підставою для злиття.
